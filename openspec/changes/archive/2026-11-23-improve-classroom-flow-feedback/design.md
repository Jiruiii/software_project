# Design

## Context

課程首頁先載入 Firebase，再恢復身分並讀取首頁資料。活動頁依身分將現有控制移至目錄；桌面固定顯示，手機則覆蓋在內容上方。

## Goals / Non-Goals

讓使用者知道正在等待什麼、錯誤後如何繼續，並讓手機教師在操作後能直接檢查作答或更正欄位。沿用目前視覺與資料模型。

## Decisions

- 用入口內的單一狀態區顯示等待或載入失敗。重試重新載入當頁，由 Firebase 還原同一個分頁的身分與路徑，避免重複註冊監聽或建立新房間。
- 只在手機目錄開啟時轉移焦點。先展開工作內容，再執行設定驗證，使表單仍能指出錯誤的欄位。結束確認的取消鍵維持安全預設。
- 保留各腳本原有的階段、權限、效能與資料斷言。官方 Sheets 範本依目前的自動同步設計驗證唯讀提示。
- 活動快照依已儲存的試算表 ID 與既有的兩份官方範本清單判斷唯讀狀態，涵蓋既有活動。其他學習單沿用實際同步狀態，直接匯出的伺服器保護持續獨立驗證。

## Risks / Trade-offs

登入失敗可能發生在 SDK、登入後讀取或返回首頁的清理流程。測試應分開模擬啟動及已登入的讀取錯誤。正式 Google 同意畫面、實際寫回和部署另以獨立證據紀錄。
