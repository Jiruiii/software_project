# Design

## Context

現有 question_meta 保存題組與參考答案，answers 保存下注與判定；_unit_points 是報告和排行共用計分來源。學生目前只輸入文字且下注最少 1 分。使用者已確認分數在同一場活動累加。

## Goals / Non-Goals

**Goals:** 單選批改在收件交易內完成，不增加外部費用；舊資料保留、題組與既有 Google 寫回相容。

**Non-Goals:** 多選、AI 批改、跨活動長期成績與學生帳號。

## Decisions

- question_meta 新增 question_type、options_json、correct_index、betting_enabled，預設簡答／空選項／無正解／開放下注。下注開關按 unit 儲存到其全部子題，原子驗證與更新；避免另一份題組資料不同步。
- POST question-settings 僅教師準備中可用，包含完整 unit 的題型設定。單選限 2～8 個選項及有效索引，原文去除外圍空白後不可重複。簡答儲存時清空單選設定。
- 下注 API 與畫面預設改 0，既有 answers 資料遷移仍補 1，不追溯變更既有分數。不押不影響是否搶答成功，只影響分數。
- 單選提交仍用現有文字答案欄位，必須完全符合已儲存選項，由伺服器比較正解並在同一交易保存 verdict。這讓結果、CSV、Google 寫回保持選項原文，不依賴前端判分。簡答保持 pending。
- snapshot 向教師傳完整設定，向學生只傳題型、選項及下注開關，永不直接傳 correct_index。學生分數只用該 session 的 answers 計算，不傳其他組統計；own_score 包含總分和待判定單位數。
- 題組只計一次，混合題組全對才加分，有錯扣分，其他待批改。已關題後的人工改判沿用現有流程，重送不覆蓋人工更正。
- 教師每個單位有設定表單；學生單選用必選選單、簡答用文字區。草稿支援兩種輸入，設定改變時重建元件並保留仍有效內容；不押的 0 不能被草稿預設值替換成 1。

## Risks / Trade-offs

- 正解外洩 → 回應明確分教師／學生欄位，測試檢查未送出學生拿不到正解。
- 關閉下注誤當不能作答 → 畫面固定不押，伺服器只拒絕非零下注。
- 多組計分被誤解為僅最快組 → 操作說明明示每組都計分，搶答成功者仍依未判錯者順序決定。

## Migration Plan

啟動時僅補缺少欄位，舊活動仍是簡答、舊下注與判定保持不變。以舊版資料庫測試遷移及重啟；更動前後不接觸使用者正式活動資料。回退前應備份資料庫。
