# Design

## Context

課堂以 SQLite、單一服務及背景倒數執行。現行 Sheets 寫入已有來源指紋、未確認寫入日誌及讀回核對。

## Goals / Non-Goals

保留原 Firebase 專案、SQLite 關聯、原表及課堂操作。此部署使用單一應用程式執行個體。

## Decisions

- Sheet 寫回使用既有的 `_leading_submissions` 選擇每個搶答單位的完整提交。任一小題判錯即排除該組整份提交，待批改仍可作為候選。保留各子題答案格與老師答案覆蓋，無候選時沿用原格核對及還原流程。

- 安裝器切換帳號前在子行程切至部署帳號家目錄。主行程保留安裝包工作目錄供後續安裝讀檔。

- 由 VM 上的 systemd 計時器每分鐘讀取 GitHub main，公開庫使用 HTTPS，私人庫使用該庫專用唯讀金鑰。首次啟用核對指定的 main 提交。專用部署帳號在獨立目錄準備程式與虛擬環境，以原子替換版本檔切換程式，重啟既有 classroom 服務並核對健康端點。保留上一版供啟動失敗時回復；資料與憑證仍由既有服務讀取。

- 依表頭及每一列的合併範圍定位。單題取作答格的左上角，題組有連續子題編號時取編號右側同列的答案格。保留子題編號於來源指紋中。若題組作答區分欄但編號已損毀，停止匯入；舊活動若指向子題編號，停止寫回並提示重新匯入。

- Azure Linux VM 使用持久 OS 磁碟，Caddy 提供固定網域 HTTPS，應用程式僅監聽 loopback；依固定來源核對 Host 與 Origin。
- 教師分享副本給專用 Google 服務帳戶，在獨立「課程設定」工作表 A1 填入課程代碼；預覽、匯入及每次寫回均核對目前來源與課程，隱藏設定分頁。官方範本仍保護。
- 無課程標記的副本以 Drive API 唯讀權限核對 anyone/writer。在授課者的預覽、建立活動及寫回前重新確認授權。匯入交易以試算表 ID 防止同一副本跨課程綁定。保存共用模式及網址提供的資源金鑰供背景重試；舊紀錄預設按私人標記查驗。
- 區分 HTTP 教師驗證與伺服器內部依活動取用既有寫回流程。從 SQLite 取回有來源且需要同步的活動，登出、重啟及改判後仍可恢復，保留寫回日誌及衝突保護。

## Risks / Trade-offs

- 單機容量與可用性受 VM 及磁碟限制。核對學生訂閱可用區域及預估費用再建立資源，保留一致備份與還原點。
- 表格分享權限或標記失效時，呈現失敗與重試；背景作業不可將其他課程資料寫入該表。

## Migration Plan

停止本機寫入、備份資料庫並核對完整性；受限傳送 Firebase 設定、資料庫及服務帳戶設定。由測試副本驗收 HTTPS 登入、來源隔離、重啟與改判，再切換師生網址。回復時保留雲端最新備份並確保只有一個寫入端。
