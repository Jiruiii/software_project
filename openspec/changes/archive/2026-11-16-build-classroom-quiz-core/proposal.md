# Proposal

## Why

建立可在本機以多個分頁演示的課堂搶答系統，讓教師控制活動、學生按小組送出答案，並保留可核對的作答紀錄。依據使用者的功能清單逐項追蹤 F-01～F-15，使用 OpenSpec 讓規格、程式與驗收證據一致。

## What Changes

- [F-01、F-02] 教師與學生分流，小組加入活動；權限在伺服器檢查。
- [F-05～F-08、F-10～F-15] 準備中、作答中、結果三階段；即時更新、組別答案、伺服器決定先後順序及結果公開。
- [F-03、F-04、F-09] 依《期末專題說明.pdf》第 2 頁官方範本，實作 Google Sheets 匯入、動態填空格定位與寫回原表。公開表可直接預覽；私人表及寫回使用 Google OAuth 電腦版應用程式。使用者選擇先完成程式再設定授權；2026-11-16 已補齊三種版面的真實授權寫回驗收。
- 提供可獨立驗證核心流程的手動題號建立方式、伺服器資料保存、自動測試、操作說明及逐項驗收紀錄。
- 使用者已確認本次只做全部 15 項核心功能；E-01～E-11 不納入。題組同時送出屬 E-09，本次偵測後明確拒絕，不拆開題組冒充單題。

## Capabilities

### New Capabilities

- `classroom-access`: 教師權限、學生身分、小組歸屬與活動隔離。
- `quiz-session`: 活動建立、階段同步、答案接收、搶答順位、結果與紀錄。
- `guided-notes`: Google Sheets 題號匯入、版面無關的填空格定位、答案原位寫回。

### Modified Capabilities

無。專案尚無既有規格或應用程式。

## Impact

新增本機 Python HTTP 伺服器、SQLite 資料庫與繁體中文 HTML/CSS/JavaScript 介面。Google Sheets REST、OAuth PKCE 與公開 XLSX 讀取皆使用 Python 標準函式庫，不需額外執行套件。不修改官方原範本；使用者複製後由活動保存來源 ID，匯出寫回該份來源。

來源：使用者功能清單 DOCX、7 頁《期末專題說明(大學部).pdf》，以及使用者指出、後續從下載資料夾找到的 5 頁《期末專題說明.pdf》。後者明列 Sheets 為核心，允許佔位符並附兩份範本。僅處理 OpenSpec 組與程式功能，不製作影片或代為提交作業。
