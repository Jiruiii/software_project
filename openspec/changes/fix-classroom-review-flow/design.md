# Design
## Context
保底只在關題時累加 group_progress；Google 寫回只在讀回成功後才保存 last_export；監看與老師答案各有一個題目選單。結果階段不區分作答結束與批改完成。
## Goals / Non-Goals
修正使用者選定的四項問題。保留待批改候選可寫回、現有分組方式、學生原始答案與分數計算規則。
## Decisions
- 保存每輪參與組別、實際先答資格及是否關閉，依目前成功者重播累計；已享有的先答重設仍照實計入。改判、批次與撤銷觸發重算，已開題資格凍結，新資格於下一題決定。
- 舊活動缺少歷史參與及保底消耗紀錄，不能可靠回推。遷移保留既有累計作為基準，從當前尚未關閉題目接續新紀錄；既有活動畫面明示歷史限制，新活動有完整紀錄。
- source_json 在送出 Google 寫入前保存 pending_export，含原格與預定值。下次操作先核對位置與結構，只接受原值或本次預定值作為恢復依據；未知內容停止。核對後保存觀察到的實際基準，再依最新判定寫入，不把未驗證寫入標成完成。
- 移除 reference-question，將 monitor-question 移至主要工作區共用；選全部或未關閉題目時老師答案區提示選已關題，不暗中選另一題。保留以活動與題號保存的草稿。
- 結果快照提供 grading 待批改數與完成狀態。排行榜、本組報告與 CSV 標示暫時成績，最後一筆批改完成自動更新；撤銷回待批改時恢復暫時成績，無人作答視為無待批改。
## Risks / Trade-offs
Google 已成功但回應遺失 → 持久化意圖可供重啟後核對；他人改格 → 拒絕覆寫。舊保底歷史不可恢復 → 保留累計且明示限制，不猜測當時組別。暫時排行榜會改動 → 顯示尚未批改數。
## Migration Plan
增量建立保底基準與逐輪紀錄表，舊活動資料不清空。pending_export 保存在原來源 JSON，沒有憑證；重新啟動後重新連線 Google 即可核對。
