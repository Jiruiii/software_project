# Design

## Context

既有 SQLite 單程序鎖、loopback HTTP、原生前端與 Google Sheets 動態定位已驗收。使用者確認本輪全部額外功能，保底採先答三秒、所有組依老師判定計分、參考答案由老師填寫。保留本機部署邊界與既有 API 預設行為。

## Goals / Non-Goals

**Goals:** 每個 E 編號獨立測試／提交；向前相容資料遷移；單一來源決定順位、判分、匯出與報告；學生結束前不知他組狀態。

**Non-Goals:** 不接 AI 判分、不部署、不建立學生帳號；相近文字不保證語意相同；保底只在單一活動內。

## Decisions

- 將額外服務邏輯集中於 quiz_extras.py，沿用 QuizService 的 RLock 與 SQLite transaction。新增選項／逐題狀態與題目 metadata；answers 增加 stake、verdict 欄位，舊答案預設 1 分、未判定。資料遷移只新增不刪除。
- 每題有 unit_id，單題是自身、題組是一組子題。提交題組使用單一交易，必須一次包含所有子題與同一下注，全部驗證後才寫入；舊單題接口不能繞過。題組候選按整組提交的最小序號排序，所有子題選同組成功者；每題組只計一次分。
- 共用 winner 計算排除 verdict=incorrect 的單位候選；pending 仍可為暫定成功者，UI 顯示未判定。評分只在全活動結束或逐題已關閉時可做。Google 匯出與結果使用同一 winner 來源，判定變更後重寫使用 last_export 核對。
- 全題模式預設無計時。逐題模式老師手動關閉／開下一題，關題時保存保底累積。保底以當時第一個未判錯候選為成功者，未成功且本題開啟前已加入者累積一次，成功者歸零；連續三次未成功者下一題有三秒先答權，使用後計數歸零，再依該題結果累計。題目關閉後的改判不回溯保底。
- 新加入組別沒有過往保底。先答資格只向學生傳回自己的狀態；其他組保底名單不公開。沒有符合資格者不延遲全班。原始收件時間永不扣秒。
- 計時設定在準備中，1～3600 秒或 0 不限時。持久化 UTC deadline，伺服器背景檢查及每次讀寫入口共同過期處理，與提交共鎖；逾時答案拒絕。逐題到期關閉當題，最後一題或全題模式到期結束活動。重啟沿用原 deadline，不重新計時。
- CSV 用 csv.writer 與 UTF-8 BOM；所有使用者文字的公式起始字元加單引號，時間以 ISO UTC 及相對毫秒輸出。老師可下載全活動，學生報告由 session 決定組別，輸出不接受任意組別 ID。
- 回放僅教師可見，使用已授權紀錄，requestAnimationFrame 控制播放／暫停／重播，不從學生 API 傳出全組歷程。
- 歸類使用 Unicode NFKC、casefold、空白整理及 difflib.SequenceMatcher，門檻 0.85；每題最多 200 個不同代表，超過時只做完全相同分類並提示，避免大量字串比對阻塞搶答鎖。
- 斷線草稿採 sessionStorage，以活動與身分識別分隔；伺服器狀態優先，已收件但回應遺失時重連顯示已送出，學生未送出文字可恢復，登出清除。
- 題組解析依題號跨列合併與子題標記，使用 1.1／1.2 等唯一內部題號，預覽顯示原題組及子題；只有可唯一判斷且完整的組別才匯入。不同欄列仍動態定位，不將題組拆成可獨立送出單題。

## Risks / Trade-offs

- 相近文字可能不同義 → UI 明示只供教師整理，絕不自動判分。
- 判分會改變先前公布結果 → 顯示判定狀態、重新匯出提示，保留原始答案與收件次序。
- 逐題先答改變預設作答方式 → 準備階段選擇模式，預設全題；開始後不能改設定。
- Sheets 外部同時編輯競爭 → 沿用前後核對及操作限制；真實題組驗收使用專用表。

## Migration Plan

服務啟動時新增缺少的欄位與表，舊資料補單題 unit_id。回歸測試使用舊 schema 的資料庫，確認活動／答案保持不變。使用者正式資料庫不作測試；需要回退版本前先備份資料檔。
