# Design

## Context

現有原生 JS 依狀態輪詢渲染，各功能已有獨立元素 ID 與 API。修改前已截圖首頁與準備頁；五題準備頁超過三個螢幕高度。保留現有資料與驗收場景。

## Goals / Non-Goals

**Goals:** 以少量前端狀態統一控制可見區域、保留欄位內容並降低每次授課操作量。

**Non-Goals:** 不換框架、不刪額外功能、不改學生計分與 Google 授權、不部署伺服器。

## Decisions

- 首頁使用兩個來源按鈕切換同一建立區；題數預設 5，自訂題號以 details 展開。相較雙表單同時展示，減少第一眼選項。
- 教師工作區選擇與活動階段分開；只在活動或階段變更時回預設頁。沿用現有 DOM，隱藏非當前區域，不重新生成輸入，避免輪詢清掉草稿。
- 老師活動頁改為頂部代碼與操作列；按鈕有「儲存設定」及「儲存並開始搶答」。逐題關題／下一題為主要動作，提早結束為次要動作。
- 設定儲存共用驗證與提交函式，先驗證全部待存欄位再逐一呼叫 API；失敗留在準備中、定位該頁及題目。跨題多個 API 不宣稱整場原子儲存，已成功者標已儲存，失敗者可重試。
- 題型採單題展開，收合摘要顯示題型與下注狀態；保留單題儲存。規則未儲存狀態也納入統一開始流程。
- 監看增加題目篩選，不改服務資料。逐題活動預設跟隨當題，手動指定後保留。批改按鈕、時間、答案留在同格。
- 將不常用工具收合，增加表單間距、活動卡片收縮與表格容器寬度限制，學生頁的面板也補上間距。

## Risks / Trade-offs

- 工具移位使舊瀏覽器測試找不到 → 更新測試實際點選新入口，仍驗證原功能。
- 輪詢把未存設定覆寫 → 僅初始化新活動，工作區切換不重建表單。
- 儲存期間重複開始或修改 → 共用鎖定狀態，暫停設定欄位及主要控制，失敗可重試。

## Migration Plan

只更新靜態檔，重新整理生效；沒有資料庫變更。回退前端提交即可恢復舊版。
