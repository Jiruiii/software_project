# classroom-hosting Specification

## Purpose

讓不同地點的師生在公開 HTTPS 網址使用同一個課堂服務，並在雲端服務重新啟動及版本更新後仍可用原 Google 身分查詢原有課程、作答紀錄與累積成績。

## Requirements

### Requirement: 從 GitHub 自動更新網站
VM SHALL 在首次核准正式版本後，定期部署 GitHub main 的新提交。每次以同一版本的前後端及相依套件啟動，沿用既有資料庫與設定。

#### Scenario: 推送及重複檢查
- **WHEN** main 更新或計時器重複檢查相同提交
- **THEN** 新提交通過準備後切換，已部署相同提交時略過重啟。其他分支及開發機本地 pull 不觸發部署。

#### Scenario: 從管理者的私人目錄首次啟用
- **WHEN** 管理者從自己的家目錄執行安裝程式，而部署帳號僅能進入自己的目錄
- **THEN** 安裝程式 SHALL 讓部署帳號從其家目錄執行 Git 及金鑰操作，並由管理者從安裝包目錄讀取部署檔案。

#### Scenario: 版本失敗
- **WHEN** 無法下載、建置失敗或新服務健康檢查失敗
- **THEN** 保留或切回原程式，記錄錯誤，資料庫與驗證設定沿用 VM 上的路徑。

### Requirement: 固定網站來源與持久課堂資料
系統 SHALL 接受設定的 HTTPS 來源，使用原 Firebase 專案及持久磁碟的 SQLite 資料庫，拒絕其他來源的瀏覽器操作。

#### Scenario: 雲端重啟
- **WHEN** 搬移既有課堂資料後重啟服務
- **THEN** 原管理員、老師、助教與學生以原帳號取得各自課程、身分及紀錄

#### Scenario: 跨來源請求
- **WHEN** 瀏覽器從設定以外的來源送出操作
- **THEN** 伺服器拒絕該操作
