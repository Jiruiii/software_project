## Chrome 流程覆蓋

| 角色與工作 | 瀏覽器案例 | 核對內容 |
| --- | --- | --- |
| 課程與帳號 | `courses` | 教師建課、學生建組、第二位學生輸錯密碼後成功加入、兩個分頁收到同組聊天與答案、剪貼簿備援、助教更正判定、學生歷史與排行榜、管理員入口、登出與恢復登入。 |
| 活動與多人同步 | `flow`、`many-groups`、`cross-priority`、`question-timing` | 開始與結束、同組同步、組間隱私、跨場先答、計時、重新整理、草稿及斷線重連。 |
| 題型與課堂操作 | `teacher-ui`、`question-types`、`multiple`、`extras` | 手動建題、自訂題號、題組、單選、多選、簡答、押分、逐題、倒數、成績、重播及 CSV。 |
| 批改與學習單 | `review-flow`、`batch-review`、`teacher-reference`、`auto-sync`、`sheets` | 單筆與批次批改、復原、學生查分、老師答案覆寫與取消、改判後同步、唯讀原表保護、手機操作。 |

30 組各答 6 題，核對教師畫面的 180 筆答案與每題贏家。使用 1 個教師分頁與 3 個代表性學生分頁，其餘參與者透過測試 API 操作。這次代表性學生分頁的開始同步最慢為 595 ms，結束為 689 ms。另以後端並行測試驗證 30 組 × 6 題 × 3 輪，共 540 筆作答、同組重送及結束邊界。

## 測試條件

- 全部 14 支瀏覽器腳本使用 Chrome、專案 HTTP handler 與隔離的 SQLite 資料。身分與 Google 寫回使用測試替身，公開範本使用專案保存的原始 XLSX。檢查涵蓋 320 與 390 px 手機版面及桌面版面。
- Python 原生 `python -m unittest discover -s tests -v` 執行 141 項，環境回報 19 個錯誤記錄，包含子案例。16 個來自 Windows 阻擋 loopback 連線，3 個來自 Git 的本機傳輸無法啟動 MSYS shell。
- 改走記憶體內 HTTP 傳輸後，138 個應用案例通過，請求仍經過專案的解析、權限檢查、資料庫與回應處理。部署的 3 個案例使用本機 Git bundle 傳遞相同的 main 提交後也通過，涵蓋版本解包、健康檢查失敗及回復。
- 試算表替身收到的寫入內容逐筆符合原驗收腳本中的預期，自動同步 5 筆，老師答案覆寫及還原 4 筆。
- 前端語法、Git 空白檢查、設計檢查及 OpenSpec 嚴格驗證均通過。針對老師答案腳本，並行測試曾在攔截的輪詢回應收尾時發生競態；修正腳本等待條件後再驗收。

## 正式站

瀏覽器實際開啟 Azure 首頁，確認學生及老師入口可切換，健康檢查回傳 `{"ok":true}`。本次修改位於本機。正式站的 Google 帳號授權、真實學生作答後寫回雲端試算表、助教改判後再次寫回，以及部署與重啟，仍待正式環境驗收。
