# 課堂搶答動態驗收

2026-11-23 於本機 Chrome 搭配隔離的 SQLite 活動資料驗收。[觀看批改操作動畫](grading-feedback.gif)

| 操作 | 驗收結果 |
| --- | --- |
| 教師判錯領先組 | 球鞋踢開答案紙，露出下一組及其判定。無人遞補時顯示「沒有其他候選答案」。判錯非領先組只更新文字。 |
| 題組的其中一題判錯 | 整組失去該題組搶答資格，遞補略過其他子題已判錯的小組。復原會重新計算候選。 |
| 判對與復原 | 判對蓋上正解章。以鍵盤判錯後可直接按 Enter 復原，紙張飛回、焦點回到原題。其他人已改判時，舊版本無法覆寫新判定。 |
| 學生交卷與三秒保底 | 本人與隊友的帳號收到不同收件文字。保底組、等待組都能看見粉筆倒數，截止後重新取得作答權限。 |
| 排行榜 | 批改完成並看到榜單後才播放。重整已有的結果可直接看到靜態榜單，兩組並列第一時各有一個星記。 |
| 手機與減少動態 | 390 像素寬可批改及復原，頁面無橫向溢出。開啟系統的減少動態偏好後，遞補文字與操作仍可使用。 |
| 輪詢與切換活動 | 重新取得作答狀態不會重播交卷、踢紙或排名。故意延後上一場批改回應，切換至下一場後才釋放，也不會出現上一場的判定或動畫。 |

## 測試範圍

- 139 項 Python 應用程式測試及 3 項本機部署腳本測試通過。部署測試使用暫存的 Git 檔案。
- 專案 15 組瀏覽器測試涵蓋主要課堂流程、課程帳號、跨場保底、批次批改、教學參考答案、題型、學習單與動態回饋。30 組小組、6 題的測試共保存 180 份答案，並逐格核對教師端監看表。
- 瀏覽器使用 Playwright 控制 Chrome。受本機連線限制，測試請求透過程序間通道交給專案的 HTTP handler。Firebase 登入與 Google Sheets 使用測試替身；本次驗收未連到正式教室或寫入正式學習單。
- 一般開發環境可執行 `python -m unittest discover -s tests`，並以 `python tests/run_extra_ui.py --suite motion` 重跑動態情境。
